Dynamic Locators & Explicit Waits

Hard general
Task: The username field has a random ID on every page load. A second field appears only after 3 seconds. A third element self-destructs after 5 seconds. The submit button stays disabled for 4 seconds. Automate the full flow without using Thread.sleep().
Live Sandbox
I vanish in 5s ⏳
waiting…
Show Java + Selenium 4 Solution 
// ✅ Never hardcode a dynamic id — use stable attributes or prefixes
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(15));

// 1. Dynamic ID — anchor on data-testid
WebElement user = driver.findElement(By.cssSelector("[data-testid='dyn-user']"));
user.sendKeys("qa_engineer");

// 1b. Alternative — match by ID prefix with XPath
WebElement user2 = driver.findElement(
        By.xpath("//input[starts-with(@id,'dyn-')]"));

// 2. Element that appears after a delay — NEVER Thread.sleep()
driver.findElement(By.xpath("//button[text()='Reveal Delayed Field']")).click();
WebElement late = wait.until(
        ExpectedConditions.visibilityOfElementLocated(By.id("lateField")));
late.sendKeys("appeared");

// 3. Element that disappears — wait for invisibility
driver.findElement(By.xpath("//button[contains(.,'Disappearing')]")).click();
wait.until(ExpectedConditions.invisibilityOfElementLocated(By.id("vanishEl")));

// 4. Button enabled after delay — use elementToBeClickable
driver.findElement(By.xpath("//button[contains(.,'Arm 4s')]")).click();
WebElement submit = wait.until(
        ExpectedConditions.elementToBeClickable(By.id("delayedBtn")));
submit.click();

// 💡 Interview tip: mention FluentWait with polling + ignored exceptions
new FluentWait<WebDriver>(driver)
    .withTimeout(Duration.ofSeconds(20))
    .pollingEvery(Duration.ofMillis(300))
    .ignoring(NoSuchElementException.class)
    .until(d -> d.findElement(By.id("lateField")).isDisplayed());

Autocomplete / Typeahead Search

Hard e-commerce
Task: Type at least 2 characters to trigger a suggestion list. Select "iPhone 15 Pro" from the dropdown — but the list re-renders on every keystroke, so a naive findElements call will throw StaleElementReferenceException.
Live Sandbox — Product Search
No product selected
Show Java + Selenium 4 Solution 
WebElement search = driver.findElement(By.id("searchInput"));
search.clear();
search.sendKeys("ip");

WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));

// Wait for the suggestion container to render
wait.until(ExpectedConditions.visibilityOfElementLocated(
        By.cssSelector("#suggestBox div")));

// ❌ BAD — list re-renders on every keystroke → stale element
// List<WebElement> items = driver.findElements(By.cssSelector("#suggestBox div"));
// items.get(0).click();

// ✅ GOOD — re-locate inside the loop and match by text
List<WebElement> suggestions = driver.findElements(By.cssSelector("#suggestBox div"));
for (WebElement s : suggestions) {
    if (s.getText().trim().equalsIgnoreCase("iPhone 15 Pro")) {
        s.click();
        break;
    }
}

// ✅ BEST — XPath text match avoids iterating entirely
wait.until(ExpectedConditions.elementToBeClickable(
        By.xpath("//div[@id='suggestBox']/div[normalize-space()='iPhone 15 Pro']")))
    .click();

// 💡 Pro move: press ARROW_DOWN + ENTER instead of clicking
search.sendKeys(Keys.ARROW_DOWN, Keys.ENTER);

// Assert the selection landed
Assert.assertEquals(driver.findElement(By.id("out02")).getText(),
                     "Selected: iPhone 15 Pro");

No file selected
Show Java + Selenium 4 Solution 
// ❌ This fails — the input has display:none, so it is not interactable
// driver.findElement(By.id("fileInput")).click();

// ✅ SOLUTION 1 — sendKeys directly on the hidden input (works in Selenium)
String absPath = new File("src/test/resources/report.pdf").getAbsolutePath();

WebElement dropZone = driver.findElement(By.id("fileDrop"));

Checkbox Groups & Radio Buttons

Medium healthcare
Task: Select exactly the symptoms "Fever" and "Cough" (and no others), then pick the gender radio "Female". Verify the selection is exclusive for radios and multi-select for checkboxes. Also test the "Select All" behaviour.
Live Sandbox — Symptom Checker
Nothing selected
Show Java + Selenium 4 Solution 
// ---- CHECKBOXES: multi-select ----
List<WebElement> allSymptoms = driver.findElements(By.cssSelector(".sym"));
List<String> wanted = Arrays.asList("Fever", "Cough");

for (WebElement cb : allSymptoms) {
    String label = cb.getAttribute("value");
    boolean shouldBeChecked = wanted.contains(label);

    // ⚠️ Always check isSelected() first — clicking twice toggles it OFF
    if (cb.isSelected() != shouldBeChecked) {
        cb.click();
    }
}

// Assert exactly 2 are checked
long checkedCount = allSymptoms.stream().filter(WebElement::isSelected).count();
Assert.assertEquals(checkedCount, 2, "Expected exactly 2 symptoms selected");

// ---- RADIO BUTTONS: single-select ----
List<WebElement> genders = driver.findElements(By.cssSelector("input[name='gender']"));
for (WebElement r : genders) {
    if (r.getAttribute("value").equals("Female")) {
        r.click();
        break;
    }
}

// Assert exclusivity — only ONE radio in the group can be selected
long radioSelected = genders.stream().filter(WebElement::isSelected).count();
Assert.assertEquals(radioSelected, 1);

// 💡 Interview tip: the isSelected() guard before click() is the #1 thing
//    interviewers probe for on checkbox questions.

Drag & Drop (Mouse-Event Based)

Expert general
Task: Drag the purple tile into the drop zone. This widget uses raw mousedown / mousemove / mouseup (not the HTML5 DnD API), so Actions.dragAndDrop() should work. Also know the fallback for HTML5 DnD.
Live Sandbox — Kanban Board
🟣 Drag Me
Drop Here
Not dropped yet
Show Java + Selenium 4 Solution 
WebElement source = driver.findElement(By.id("dragItem"));
WebElement target = driver.findElement(By.id("dropZone"));

// ---- METHOD 1: the simple one-liner ----
new Actions(driver).dragAndDrop(source, target).perform();

// ---- METHOD 2: manual click-and-hold (more reliable, more human-like) ----
Actions act = new Actions(driver);
act.moveToElement(source)
   .clickAndHold()
   .pause(Duration.ofMillis(500))   // let the UI register the drag start
   .moveToElement(target)
   .pause(Duration.ofMillis(300))
   .release()
   .perform();

// ---- METHOD 3: offset-based (when the target centre is wrong) ----
act.moveToElement(source).clickAndHold()
   .moveByOffset(200, 0)
   .release().perform();

// ---- METHOD 4: JS fallback for HTML5 native drag-drop ----
String js =
  "function createEvent(type, el){var e=document.createEvent('DragEvent');" +
  "e.initEvent(type,true,true);el.dispatchEvent(e);}" +
  "var s=arguments[0], t=arguments[1];" +
  "createEvent('dragstart',s); createEvent('drop',t); createEvent('dragend',s);";
((JavascriptExecutor) driver).executeScript(js, source, target);

Assert.assertEquals(driver.findElement(By.id("out16")).getText(),
                     "Dropped successfully! ✅");

// 💡 Interview tip: the killer answer is knowing that Actions.dragAndDrop()
//    FAILS on HTML5 draggable="true" elements and you need the JS fallback.

Live Sandbox — Live Transaction Feed (auto-refreshes every 3s)
Refreshing in 3s…

Show Java + Selenium 4 Solution 
// ---- ❌ THE NAIVE (FLAKY) APPROACH ----
List<WebElement> rows = driver.findElements(By.cssSelector("#liveBody tr"));
for (WebElement r : rows) {
    r.findElement(By.cssSelector("button")).click();   // 💥 StaleElementReferenceException
}

// ---- ✅ SOLUTION 1: RE-LOCATE inside the loop ----
int rowCount = driver.findElements(By.cssSelector("#liveBody tr")).size();
for (int i = 0; i < rowCount; i++) {
    // Fresh lookup by INDEX on every iteration
    WebElement btn = driver.findElements(
            By.cssSelector("#liveBody tr")).get(i)
            .findElement(By.cssSelector("button"));
    btn.click();
}

// ---- ✅ SOLUTION 2: RETRY WRAPPER (production-grade) ----
public void clickWithRetry(By locator, int maxAttempts) {
    for (int attempt = 1; attempt <= maxAttempts; attempt++) {
        try {
            new WebDriverWait(driver, Duration.ofSeconds(5))
                .until(ExpectedConditions.elementToBeClickable(locator))
                .click();
            return;                       // success
        } catch (StaleElementReferenceException e) {
            System.out.println("Stale on attempt " + attempt + ", retrying…");
        }
    }
    throw new RuntimeException("Element stayed stale after " + maxAttempts + " attempts");
}

// ---- ✅ SOLUTION 3: ExpectedConditions.refreshed() ----
new WebDriverWait(driver, Duration.ofSeconds(10))
    .until(ExpectedConditions.refreshed(
        ExpectedConditions.elementToBeClickable(By.cssSelector("#liveBody tr:nth-child(1) button"))))
    .click();

// 💡 Interview tip: explain the ROOT CAUSE — the DOM node was replaced, so the
//    cached WebElement reference points to a detached node. The fix is always
//    "re-locate the element", never "add Thread.sleep()".

Task: Scroll the container to load more products. Keep scrolling until "Product #50" is present or the "End of results" marker appears. Then scroll back up and verify the first item is still there.
Live Sandbox — Product Feed (infinite scroll)
Scroll down to load more…

Show Java + Selenium 4 Solution 
JavascriptExecutor js = (JavascriptExecutor) driver;
WebElement box = driver.findElement(By.id("scrollBox"));

int previousCount = 0;
int stableRounds  = 0;
int maxScrolls    = 30;

for (int i = 0; i < maxScrolls; i++) {

    // Scroll the INNER container, not the window
    js.executeScript("arguments[0].scrollTop = arguments[0].scrollHeight;", box);

    // Give the AJAX loader a moment to append rows
    try { Thread.sleep(600); } catch (InterruptedException ignored) {}

    int currentCount = driver.findElements(By.cssSelector(".lazy-item")).size();

    // Stop condition 1: we found the target item
    if (!driver.findElements(By.xpath(
            "//div[@class='lazy-item'][contains(.,'Product #50')]")).isEmpty()) {
        System.out.println("Found Product #50 after " + i + " scrolls");
        break;
    }

    // Stop condition 2: nothing new loaded twice in a row → end of feed
    if (currentCount == previousCount) {
        if (++stableRounds >= 2) {
            System.out.println("Reached end of feed. Total items = " + currentCount);
            break;
        }
    } else {
        stableRounds = 0;
    }
    previousCount = currentCount;
}

// Scroll back to the top and verify the first item survived
js.executeScript("arguments[0].scrollTop = 0;", box);
Assert.assertTrue(driver.findElement(By.cssSelector(".lazy-item"))
                       .getText().contains("Product #1"));

// 💡 Interview tip: the "stableRounds" guard is what interviewers want —
//    it prevents an infinite loop when the feed genuinely ends.
//    Note: a fixed Thread.sleep here is acceptable ONLY as a poll interval;
//    a WebDriverWait on item-count growth is the cleaner alternative.

// ================================================================
// PART 1 — Extract a single row into a Map<Header, CellValue>
// ================================================================
public Map<String, String> getRowAsMap(String customerName) {

    List<WebElement> headers = driver.findElements(
            By.cssSelector("#custTable thead th"));

    List<WebElement> rows = driver.findElements(
            By.cssSelector("#custBody tr"));

    Map<String, String> rowData = new LinkedHashMap<>();

    for (WebElement row : rows) {
        List<WebElement> cells = row.findElements(By.tagName("td"));
        if (cells.isEmpty()) continue;

        // Match by the Name column (index 1) — dynamic column order safe
        if (!cells.get(1).getText().trim().equalsIgnoreCase(customerName)) continue;

        for (int c = 0; c < headers.size(); c++) {
            rowData.put(headers.get(c).getText().trim(), cells.get(c).getText().trim());
        }
        break;
    }
    return rowData;
}

Senior-Level Interview Q&A (5+ Years)

Expert reference

Q1. Your test passes locally but fails on the CI grid. How do you debug?

First, reproduce with the same browser/version and headless flag — headless Chrome renders differently (viewport, fonts, animations). Enable a screenshot-on-failure listener plus Extent Reports attachments. Check for: missing explicit waits (grid is slower), file-upload paths (need LocalFileDetector), screen resolution affecting element visibility, and parallel execution sharing driver state. Use a ThreadLocal<WebDriver> for thread safety.

Q2. How do you decide between implicit, explicit, and fluent waits?

Never mix implicit and explicit — they compound unpredictably. Use explicit waits only, scoped to specific conditions. Use FluentWait when you need custom polling intervals or to ignore specific exceptions. Implicit waits are a global band-aid and hide real synchronisation bugs.

Q3. How would you architect a framework from scratch?

Layered: (1) DriverFactory with ThreadLocal for parallel execution; (2) Page Objects with @FindBy + PageFactory or a custom ElementActions wrapper; (3) Test layer with TestNG + DataProviders; (4) Reporting via Extent Reports with ITestListener; (5) Config via owner/config.properties for env switching; (6) CI via Jenkins/GitHub Actions with Selenium Grid or Docker. Add a RetryAnalyzer for flaky tests and log every failure with a screenshot.

Q4. How do you handle a flaky test that fails 1 in 20 runs?

Never just add retries. First, classify: is it product flakiness, test flakiness, or infra flakiness? Capture the DOM snapshot + screenshot + browser console logs on failure. Common root causes: missing wait on an async state change, animation timing, shared test data between parallel tests, or a stale element. Fix the root cause; use IRetryAnalyzer only as a temporary safety net and track the retry rate as a metric.

Q5. How do you test REST APIs alongside your UI tests?

Use Rest Assured for API-level setup and teardown to make UI tests faster and more deterministic — create test data via API instead of clicking through the UI. Validate the contract with JSON Schema, use given().spec(requestSpec).when().get("/endpoint").then().statusCode(200).body("id", notNullValue()). For hybrid tests, log in via API, inject the session cookie into the browser, and jump straight to the target page.

Q6. How do you integrate Appium into the same framework?

Abstract the driver creation behind a factory: WebDriver for web, AndroidDriver/IOSDriver for mobile — both implement WebDriver, so Page Objects can be shared where UI patterns match. Keep separate locator strategies (Accessibility ID / UiAutomator for Android, XCUITest for iOS). Run on a real device cloud (BrowserStack/Sauce Labs) or a local Appium server with UiAutomator2 driver. Use the --relaxed-security flag only in non-prod.

Q7. How do you generate a professional Extent Report?

Use ExtentSparkReporter with a custom theme and system info. Attach screenshots to failures via test.fail("msg", MediaEntityBuilder.createScreenCaptureFromPath(path).build()). Implement ITestListener to hook onTestSuccess/Failure/Skip and a @BeforeMethod to create the test entry. Always include the environment, browser version, and base URL in the report header — reviewers need that context.

Q8. Your locator breaks after a UI redesign. How do you future-proof?

Advocate for data-testid attributes agreed with the dev team. Prefer stable semantic attributes (name, aria-label, role) over auto-generated CSS classes like css-1x9k2. Centralise locators in Page Objects so a change touches one file. Use relative locators (Selenium 4 RelativeLocator.with()) for layout-based relationships. Never use absolute XPath like /html/body/div[3]/div[2]/span.

Q9. How do you reduce a 4-hour regression suite to under 40 minutes?

(1) Parallelise with TestNG parallel="methods" + ThreadLocal drivers on a Grid/Docker. (2) Replace UI setup with API calls. (3) Run only a smoke subset on every commit, full regression nightly. (4) Eliminate redundant Thread.sleep() — measure and remove. (5) Use headless mode for CI. (6) Remove duplicate coverage between UI and API layers. (7) Profile the slowest 20 tests — they're usually 60% of the runtime.

Q10. How do you handle dynamic test data across parallel runs?

Generate unique data per thread — append System.currentTimeMillis() or a UUID to usernames/emails. Never share a fixed test account across parallel threads. Use a JSON/Excel DataProvider with thread-safe indexing, or generate data programmatically. Clean up via @AfterMethod API deletes so runs are idempotent and repeatable.
